# Briefing

## Design Decision

The briefing is **deterministic and template-composed** -- not generated by an LLM. See [ADR-002](../decisions/002-no-llm-in-app.md) for the rationale.

This means:
- No API key required
- No per-message cost
- Works fully offline
- Structurally incapable of inventing a health claim
- Assembled from a phrase bank with conditional branches over the user's logged data

## Morning Briefing

Shown at the top of Today on first open each day, expandable to `/briefing`. Contains:

1. Today's actual Brahma Muhurta window and wake/bed targets for their location
2. Current dosha period and what it suits
3. Today's training session and whether it is a deload week
4. Fuel rule for that session
5. Any live advisories from the rules engine
6. One science card of the day (deterministic rotation)

## Evening Review

Available at `/briefing?kind=evening`. Contains:

1. What was completed today
2. The three tracked numbers (average sleep, resting HR trend, hard-task-before-noon rate)
3. Prompt for tomorrow's single most important task
4. Wind-down cue
5. Tomorrow's recomputed windows (wake, Brahma Muhurta, bedtime)

## Implementation

- `lib/briefing.ts` -- `composeMorningBriefing()` and `composeEveningBriefing()`
- `app/briefing/page.tsx` -- briefing page
- `app/api/briefing/route.ts` -- API route (GET with `?kind=morning|evening`)
